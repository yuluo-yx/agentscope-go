# Daytona Workspace Example

Project home: [README.md](../../../README.md).

Chinese documentation: [README-zh.md](README-zh.md).

This example demonstrates an agent-driven Daytona workflow:

- Create a Daytona sandbox from a Python image.
- Upload a fixture CSV from `data/sales.csv`.
- Give an Agent the CSV schema and the user task.
- Attach the Daytona workspace to the Agent with `agent.WithWorkspace(ctx, ws)`.
- Let the Agent generate Python code from that schema.
- Execute the generated Python through a custom `RunPythonAnalysis` tool added with `agent.WithAdditionalToolkit`.
- Return a final conclusion that includes the data source and generated artifact paths.

The checked-in `python_runner.py` is only a small executor wrapper. The analysis code is generated by the Agent at runtime and written into the Daytona sandbox before execution.

## Prerequisites

- Go 1.26.4.
- A Daytona account or compatible self-hosted Daytona API.
- `DAYTONA_API_KEY`, or the Daytona JWT environment variables supported by the SDK.
- A DashScope chat model key: `DASHSCOPE_API_KEY` or `AI_DASHSCOPE_API_KEY`.

Optional variables:

- `DAYTONA_API_URL`: custom Daytona API URL.
- `DAYTONA_TARGET`: Daytona target/region.
- `AGENTSCOPE_DAYTONA_IMAGE`: image for new sandboxes, default `python:3.12`.
- `AGENTSCOPE_DAYTONA_KEEP_SANDBOX=true`: keep the sandbox after the example exits.
- `DASHSCOPE_MODEL`: DashScope model name, default `qwen-plus`.

## Run

```bash
cd example/workspace/daytona
go run .
```

Output includes:

...
